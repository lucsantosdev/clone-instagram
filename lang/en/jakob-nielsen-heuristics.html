A concise guide to reviewing interfaces with a focus on usability. Use this list in audits, prototype testing, and flow refinement before final development.

How to use this guide

For each heuristic, check if the interface communicates what is happening, prevents errors, and respects the user's mental model. Mark friction points and prioritize adjustments that reduce cognitive effort.

1. Visibility of system status

Provide clear feedback on loading, success, error, and task progress.

2. Match between system and the real world

Use familiar language, understandable icons, and flows aligned with the user's context.

3. User control and freedom

Allow undo, cancel, and back actions without losing progress.

4. Consistency and standards

Maintain predictable behaviors, naming conventions, and components throughout the experience.

5. Error prevention

Prevent errors with proactive validations, input limits, and confirmation actions when necessary.

6. Recognition rather than recall

Reduce cognitive load with visible options, history, and contextual cues.

7. Flexibility and efficiency of use

Accommodate both beginners and advanced users with shortcuts, autofill, and quick paths.

8. Aesthetic and minimalist design

Remove visual noise and highlight only what is essential for the current task.

9. Help users recognize and recover from errors

Error messages should explain the cause, impact, and next steps for correction.

10. Help and documentation

Provide easily accessible support with clear guidance and ready-to-use examples.
